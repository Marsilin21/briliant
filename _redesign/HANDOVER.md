# Передача и демонстрация

Проект: `A:\сайты\монолит`. Дата: 7 сентября 2026. Домен ещё не переключён.

## Что показать заказчику

1. Открыть `CLIENT_REPORT.html`: итоги, реальные примеры до/после, назначение каждой страницы, раскрывающиеся метаданные и FAQ. Файл работает самостоятельно и не содержит паролей. `CLIENT_REPORT.md` — текстовая версия.
2. Открыть http://127.0.0.1:4180/ на компьютере с работающим проектом: сохранённое оформление, виды ремонта и согласованные цены.
3. Сравнить `/design` и `/avtorski-nadzor`: разные результат, этапы и ответы. Затем `/kap-remont`, `/remont-v-novostroyke`, `/remont-vtorichnogo-zhilya`: разные задачи посетителя.
4. В http://127.0.0.1:4180/admin/ показать тексты и SEO, предложения, портфолио и заявки. Данные первоначального входа — локальный `data/initial-admin.txt`; не включать этот файл в клиентский отчёт и не пересылать весь каталог данных.
5. Для демонстрации редактирования сохранить черновик и открыть предпросмотр. Публикация изменяет локальное содержимое; восстановление версии сначала создаёт черновик и требует отдельной публикации.

Тестовая заявка и тестовая публикация проверялись в отдельной временной базе, поэтому их нет в рабочем разделе заявок. На рабочем сайте отправка создаст настоящее локальное обращение.

## Запуск

Node.js 24. Из каталога проекта:

```powershell
npm ci
npm run build
npm start
```

Для обычного запуска уже установленного проекта достаточно `npm start` или `start-monolit.ps1`. Сервер слушает 127.0.0.1:4180. Если порт занят работающей версией, второй экземпляр запускать не нужно.

## Воспроизводимая проверка

```powershell
npm run build
npm test *> _redesign/RELEASE_TESTS.txt
node scripts/release-audit.mjs
node scripts/client-report.mjs
```

После изменения кода перезапустить сервер перед обходом. Аудит проверяет фактически работающий экземпляр. `BROWSER_QA.json` — запись наблюдений текущей браузерной сессии; генератор отчёта не повторяет визуальную проверку. При изменении интерфейса её нужно провести заново и обновить запись.

Последняя проверка: 32 теста, 17 страниц, 111 ресурсов, 30 контекстных ссылок, 0 ошибок обхода. Для поиска причин смотреть `RELEASE_TESTS.txt`, `RELEASE_AUDIT.json` и `BROWSER_QA.json`.

## Данные и обновление

- Пользовательские данные: `data/monolit.sqlite` и `data/uploads/`. Не заменять этот каталог при обновлении кода.
- Перед обновлением выполнить `npm run backup`; хранить копию вне публичной раздачи. Согласованный снимок перед последней доработкой: `backups/2026-09-07T15-19-51-538Z`.
- Для корректной миграции сохранить `scripts/legacy-content-v1.json`, `scripts/seo-baseline-v2.json`, `scripts/editorial-baseline-v3.json`. Это неизменяемые исходные снимки для отличия заводских текстов от редакторских правок.
- Подробности восстановления, переменные окружения, роли и Docker — в `README.md`.

## Финальный запуск на домене

Оставшиеся фактические пробелы перечислены в `STATUS.md` и клиентском отчёте. После заполнения контактов, реквизитов, политики и сведений об объектах подключить нужные уведомления и аналитику; проверить доставку. Затем проверить развёртывание на хостинге, HTTPS, резервную копию и домен. Локальная закрытая индексация не должна переноситься на публичные коммерческие страницы; production-режим покрыт отдельным автотестом, но нуждается в проверке после развёртывания.

Запуск контейнеров на VPS, реальные поисковые показатели, внешние кабинеты и переключение brilliant-monolit.ru в текущую проверку не входят.
